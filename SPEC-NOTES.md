# Standing v0.1 — implementation deltas after review

`SPEC.md` is the original build spec. These notes record corrections and hardening made after an independent code review and a live run; they take precedence where they differ from the spec.

## New owner settings

| Setting | Default | Delta from SPEC v0.1 |
| --- | --- | --- |
| `file_proof_roots` | `[]` → configured workspace | File proofs are no longer arbitrary readable paths. The owner selects absolute artifact directories or exact files. Empty roots use only `workspace`; no configured workspace/roots means refuse. Known credential paths and HERMES_HOME outside workspace are forbidden even under a broad configured root. Requested and resolved names are checked; no-follow descriptor traversal prevents leaf/parent symlink swaps at open time. |
| `http_proof_targets` | `[]` → disabled | A model-supplied URL alone is not authorization. The owner must allow the same origin and path: trailing slash allows a subtree, otherwise exact endpoint. Query must match exactly; no caller-appended query data. Reject outside scope before opener/connect; continue refusing redirects, ambient proxies, credentials and ambiguous traversal. This is not DNS/IP pinning or proof a configured server is safe. |
| `db_path` | empty → existing profile-local plugin_db | Optional same-machine shared SQLite path. Governor commands/table and worker proofs/gates use the same explicitly selected file. Empty keeps the SPEC's plugin_db behavior and documented fallback. No automatic discovery, import, merge or deletion of local ledgers. Owner-coordinated backup/canonical-ledger migration is required before changing established profiles to shared storage. |

All three settings appear in `Settings`, registration, `plugin.yaml`, and the README settings table. Paths are absolute (with `~` expansion); settings are owner-loaded, not standing_proof arguments. Shared participants must use the same `db_path` and consistent earning/seed settings. Defaults and seeds only create missing actors; neither raises nor lowers existing levels at load. Explicit owner commands and completed, mismatching proofs still lower levels by design. Existing home-local databases are untouched by opting into a different file; selecting an empty database starts a new record, not an implicit migration.

## Corrections/clarifications without new settings

- **F2:** Cron actions are explicit: read `list/get/show/status`; spin `create/add/update/edit/resume/enable/run/trigger`; scrub `remove/delete/clear/pause/stop/disable/cancel`; everything else unknown. Pausing/stopping/disabling is deliberately scrub because it disrupts scheduled work. Host support for aliases is not asserted.
- **F3:** Exit-code and timeout checks already existed; their tests now print the matching marker before failing/sleeping. Mutation evidence proves the new tests catch each removed guard, unlike the old tests.
- **F6:** Command stdout is no longer a temporary-file spool. A bounded in-memory 2 MiB payload buffer plus a single overflow-detection byte is used; overflow fails even with an early match, stops reads and kills/reaps the command group. A wall-clock timeout includes pipe reads and waiting after stdout closes. This POSIX implementation targets Linux/macOS; it is not a process/container sandbox. README distinguishes transient buffers from metadata persisted in SQLite.

## Live-run integration corrections

- **Deferred tools:** `Standing.before('tool_call', ...)` unwraps every inner name/arguments pair, including nested wrappers, and uses the same direct-call policy and same-session/task completion proof check. Results aggregate as block > approve > none without skipping later calls. Malformed/empty calls request approval; a malformed payload containing an inner `kanban_complete` name blocks, even after a prior proof. Protected completion still fails closed on identity/storage errors. `tool_describe`/`tool_search` stay read-only classifications.
- **Usable L2:** the new `shell` category covers terminal/code calls without recognized scrub/send/spin matches, including shell composition/metacharacters and the former tiny `pwd`/`git status` read exceptions. Both `terminal.command` and `execute_code.code` retain recognized risk categories. Defaults are L0 `[read]`, L1 `[read, local_write]`, L2 `[read, local_write, shell, send, spin, unknown]`, L3 `['*']`. This intentionally stops treating an unknown/shell operation as automatic unattended denial at L2; recognized scrub/spend still request approval below L3. Existing workspace bounds for file-write categories are unchanged; shell permission does not claim workspace confinement or parsing/sandbox enforcement.
- **Settings/docs:** `shell` is accepted in owner category maps; runtime, README and plugin manifest defaults agree. Explicit old owner L2 lists are not silently migrated: remove the override or add shell/unknown and reload to use the new policy. Original SPEC is unchanged.

## Task-card visibility

- `card_line: true` (strict bool, default true) adds a best-effort `post_tool_call` observer for actual successful `kanban_complete` results. It requires the same actor/task/session passing receipt; errors/failed completion/no receipt produce no success line. The in-memory receipt now stores only kind and safe HTTP host. Current ledger passes-window and lifetime-fail counters are labeled separately, not misleadingly combined into one window.
- A failing proof that lowers level adds one generic demotion comment when assigned task is known. The old level is returned by `Ledger.proof` inside its transaction; there is no racy pre-proof lookup or ledger schema migration.
- Both paths use native `kanban_db.add_comment` / `kanban_db_connect.connect`, same connection seam as `kanban_tools._board`. Board args are forwarded, env/current-board/fence resolution belongs to the host. No shell-out or separate store. Comment exceptions are type-only warnings; completion/proof results remain unchanged. One completion attempt is guarded in memory before storage I/O to avoid duplicates after ambiguous committed-write errors.
- False disables comments only. Expected text, full URLs/query/port/path, command argv and file paths never enter comments. README now includes `What the owner sees`, approval text, card examples and the persistent-hostname disclosure. Native dispatch/visible-card acceptance remains a host release check, not claimed by stubbed registration tests.

## Proof fairness

- Proofs now distinguish `pass`, `fail` (a completed mismatch), and `unavailable` (not safely executable/available). The runner uses `passed=None` for unavailable; tool JSON adds `result` and returns `passed: null` in that case. Existing pass/fail booleans retain their meaning.
- Unavailable attempts append an `unavailable` event without changing actor level, pass window, lifetime failures or timestamp. They issue no receipt or card line and do not satisfy completion. Fixed guidance explains host-side file proofs and owner-allowlisted HTTP/command alternatives without exposing raw targets or exceptions. Existing scope, timeout and output-budget guards remain enforced.
- Review hardening: incomplete advertised HTTP bodies within the proof prefix are unavailable even with an early matching marker. Malformed, comma-combined or duplicate Content-Length fields are refused as unavailable, preventing urllib from silently treating a declared body as unbounded. Malformed non-string `kind` values log under `invalid` instead of causing an unrecorded handler error. All concrete review findings have regression tests.
- Seeds/defaults now initialize missing rows only; seeds never update existing actors, counters or history at load. Repeated worker or governor registration against a shared ledger preserves demotions, owner changes and pass windows. Restarts never undo a demotion. Owner manual changes use `/standing set`; normal proof-based promotion/demotion is unchanged. No seed schema/data migration is needed and past restorations are not reversed.
- No schema migration: the existing events result text supports `unavailable`; historical events are retained, not reclassified.
